## 3. DEFECTS

None that change a registered number. Two latent items:

D1 (latent, no live effect). `p.ant_spacing_wl` is recomputed from `p.n_rx` only inside `build_threat_model.m:2203` (`antenna_defaults`), but `link/idle_rssi.m:128`, `link/emitter_idle.m:96` and the extraction read the caller's `p`. If a caller overrides `p.n_rx` after `init_params` without rebuilding the spacing and then runs the idle model, the model and the idle record use two different spacings. In production `p` always comes from `init_params` (formula identical, `init_params.m:325`), and `validate_phy` cases with n_rx = 1, 2, 3 do not call `idle_rssi`, so nothing is wrong today. Evidence: the two formulas differ only by `max(n_rx-1,1)` vs `(n_rx-1)`. Fix would be one helper used by both; not urgent.

D2 (fragile ground truth). `extract_closed_loop_frames.m:250-254`: if `Thr_act` is shorter than `nf` the last value is repeated (`F.act(end+1:nf) = F.act(end)`) with no message, and a thrown error falls back to `ones` (see P9). Cannot happen with the current model; listed because it fails silently.

## 4. Efficiency notes for the physical layer (measured data used)

D91 profile (`uav-gcs-logs/v7_d91_speed_profile.log`, jamming, 20-frame run, mean of 3 flights): link_seed 0.093 s, **sim 2.198 s**, extract 0.755 s (of it **idle_rssi 0.516**, mmse_predict 0.041), detector part 0.231 s, build 2.4 s once per configuration. So per run: sim 66 %, idle_rssi 15 %, link_seed 3 %, rest of extract 7 %, detector 7 %. `lag_channels` 0.024 s, `residual_metrics` 0.02 s, `spec_image` 5.5 ms per frame: not worth touching. Pools are already built once per configuration (`pool_cell.m:40-50`), twins share their run, cell order and parfor were done in D91, so there is no repeated model build inside a cell.
Not measurable from the logs (Simulink profiler returned no block data): the split of the 2.2 s of `sim` between compile/initialisation per `sim()` call and the 20 frames. The log shows "Collecting compile statistics" once per run, so every run recompiles after the `set_param` calls of `link_seed`. `Simulink.FastRestart` cannot be used as is: the AWGN and Bernoulli seeds (non-tunable) change every run. A 5-minute check in `dev/dev_d91_profile.m` (time `sim` for StopTime of 1 frame vs 20 frames) gives the fixed part; if it is more than ~0.5 s, one `sim` per flight pair would be the next lever. No proposal is made without that number.
The per-frame cost inside `Rx` (3 whitening hypotheses x FFT 512 over the arrival window, space-time sync in `st_sync`, equalizer passes) is in compiled block code; I found no repeated filter or channel construction in the generated scripts that could be removed without changing the numeric path (`rxf` and `txf` are `persistent`, the sinusoid sets `f0/ph/fT/pT` are drawn once per run).

## 5. Contracts that bind the proposals

- `params_id` is an MD5 of `jsonencode(params)`: any field added, removed or reordered in `init_params.m` changes it. The legacy block `init_params.m:417-420` (`num_frames`, `seq_len`, `seq_stride`) has no reader anywhere (also `mod_type` and `samples_per_symbol` are read only by `init_params` itself) and its comment names a `run_awgn_sweep.m` and `legacy/` code that are not in the tree; removing them would change `params_id`, so it waits for a full re-key. Not proposed.
- `detector_id.m` hashes `trained_at, ood.score, ood.win, FZ.FM, FZ.N, FZ.q_thr`: no file in my area computes anything that flows into it differently after any row above. `fusion_rev_id.m` builds a string from `fit` and `fusion_pick().ext`: untouched.
- Code SHA-frozen by D111 (`ood_k2_run.m:61` RULE list, `k2_1_screen.m:44`): `ood_k2_run.m, ood_k2_rules.m, ood_cue.m, unk_stat.m, unk_write.m, ood_loto_split.m, k2_1_screen.m`. A comment edit in any of them breaks `ood_k2_run:rule_changed` (line 205).
- `random-number order`: `build_threat_model.m:217` draws `randi` from the global stream when `p.seed` is empty (P3, P14). Idle model streams (`ctx.seed+7`, `+5`) are private (`RandStream`), the global stream is never touched by `idle_rssi`.
- Source-text tests (`fileread(which(...))`) exist for `select_fusion` (13), `run_dataset_sweep` (11), `eval_detector` (10), `extract_spectrograms` (8), `compare_architectures` (6), `prepare_data` (6), `ood_k2_run` (3), `eval_ood_detection` (3), `build_threat_model` (2), `eval_unseen_snr` (2), `train_detector`, `train_core_cnn`, `unk_stat` (1 each): any edit in these files must be checked against those strings first.
