## Summary

State: no function file in `decision/` is dead (every one has a caller in `code/`; `profile_forced_fields.m` is called by the release check in `tests/test_smoke.m`). There is no `try/catch`, `eval`, `global` or absolute path in either folder. `dev/` is provenance for registered calibration constants (DECISIONS, `docs/d91_speed.md`, `docs/runs/*.sh`) and stays.
The real weight is in copy-paste helpers (13 `ternary`, 8 `cp_upper`, 4 `cat_struct`, 3 clean-episode builders, 4 copies of the detector set-up) and in a few ~100-line report blocks. DQN training does NOT reload or recompute large data inside its loops; `policy_pools.mat` (14 GB, profile 1) is loaded once per stage (C1d, C2, C2e, C2g, C2u, and the two C1c builders), and `clean_world.m` and `clean_ber_ref.m` are already cached.
Run-hours (derived): C2 took 2 359 min for 83 trainings = 28.4 min each (DECISIONS/PROJECT_LOG: 81 runs + 2 retrains). The current grid (4 monitors x 3 drops x 3 penalties x 3 seeds = 108, plus up to 9 coordinate runs and 2 retrains) is about 116-119 trainings = 55 h per profile. From v6 (C2 20.2 min per training, C2g 15.5 min per entity incl. one training) about 25% of a C2 training is evaluation (about 7 min per training, about 14 h per profile). So a 1% cut per training is worth 0.55 h per profile. Everything that is bit-identical and safe saves under 2%; the larger savings (section N) change numbers or the orchestration and need a decision.
Top 5 proposals: (1) one shared `ternary` / `cp_upper` / `cat_struct` / `file_sha256` (rows 1-3, 8), zero run effect, removes about 150 duplicated lines; (2) one clean-episode builder instead of three (row 5); (3) one `leave_out_episodes` helper for C2g and C2u (row 4); (4) persistent `decision_config` and a lookup table in `feature_index` for the per-step hot path, est. 0.5-1.5 h of C2 (row 12, profile first); (5) strip the ~40 decision-tag comment lines the 30.09 pass could not have caught (row 14).
Contracts that constrain every row: (a) `run_cache('inputs')` hashes the bytes of every `code/**/*.m` (comments included, tests/legacy excepted), so any edit, even a comment, changes the key of every cached C2/C2g/C2u run; apply only between chains, never under a running stage (past bug 13); (b) `tests/test_d107.m:961-963, 1112-1116` cuts `select_run..with_nb`, `cp_upper..fa_txt`, `ternary..relm_score` and the `admp = [ADM(` .. `APL = [{''''}, APL];` block out of the TEXT of `train_dqn.m`; `tests/test_lb.m:134,153` and `lb_selfcheck.m:13` read the text of `lb_complete.m` and of `lb_track` in `policy_monitor.m`. Any move out of those files needs the test edited in the same commit; (c) the printed lines I checked (`The kept fusion is the rule's base`, `-> rule yes`, `DEPLOY_STATE`, `V7SMOKE`, `V7RELEASE`) are not produced by `decision/` or `dev/`; none of the rows below changes a printed line.

Generic equivalence harness G (used in the "proof" column): on a scratch copy of the tree (not the worktree the chain reads, and not while p1.log shows C2/GAL/EDGE/WEAK, past bugs 11 and 15) run `run_stage('smoke','C1d','C2','C2e','C2g','C2u')` with `CFG.smoke_all_entities = true`, old code and new code, and compare `data/trained_dqn.mat`, `results/policy_evaluation.mat`, `combo_generalization.mat`, `unknown_threat_policy.mat`, `data/drop_threshold.mat` with `isequaln` (fields by name) and the `results/*.txt` files with the `Generated:` and `(x min)` text masked. ## DEFECTS (behaviour, with evidence)

None that changes a saved number today. Two traps found:

1. `CFG` from `main.m` never reaches the headless chain. `run_stage.m` runs every script inside `run_one` (run_stage.m:67-126), a function that never defines `CFG`, so `exist('CFG','var')` is false in train_dqn.m:136,162,174,182, choose_drop_threshold.m, evaluate_policies.m:110 and the experiments, and the built-in defaults apply. The values in main.m:90-96 (`dqn_seeds 3`, `monitors` x4, `drop_steps [-2 0 2]`, `fa_penalty_grid [80 120 160]`, `cost_scale_grid [0.5 0.5 0.5]`) equal those defaults (train_dqn.m:152-159, decision_config.m:15-17), so nothing differs now. Anyone editing main.m's `CFG` for a `run_stage` chain would be ignored without a message; the switches that do reach the chain are the ones read from `profile.json` (`wf_options`, `run_cache`, `lb_options`, `speed_options`). Suggest an assert in `run_one` or one source of defaults.
2. `cp_upper` has two behaviours at n = 0 (row 2): 1 in train_dqn/evaluate_policies/lb_adopt/nb_pick/aprime_admit, NaN in choose_drop_threshold/clt_step/dconf_step. No path I traced reaches n = 0 with a printed or saved effect (train_dqn guards `isnan(fa_w)` at 1091, 1101, 1041), but a naive merge would change them.
