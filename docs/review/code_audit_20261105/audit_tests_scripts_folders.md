# Audit: tests, run scripts, folders, docs (5.11.2026, read only)

Scope: `code/tests` (10 files, 20,250 lines), `uav-gcs-logs\*.sh|*.ps1`, the 17 sibling folders plus `d91q` (an 18th, found in the user folder) and the main folder's `worktrees\`, and the docs in `uav-gcs-v7-docs`. Nothing was run, moved, deleted or changed. No MATLAB, no git state change. Sizes are `du` of 5.11 (the 36 GB / 113 GB folders were measured, not copied from the brief).

## 1. Summary

- **Tests.** 316 test functions in test_core (about 54-64 min per full run on the deploy queue, twice per queue round) and 269 more in nine other files. No test lacks an assertion, but two tests in `test_d121.m` assert only their own local arithmetic. The same 3-5 helper functions are copied 7 times across the files. The release queue (`v7_d91_deploy_tests2.sh:131`, `v7_d91_tests2.sh:52-54`) runs only `test_core.m`; test_core wraps `test_deg_mode` and `test_ood_k2` as nested suites, so the other **seven files (225 tests) are never run by any queue script**, and `runtests('code/tests')` runs the two nested files twice.
- **Scripts.** Live now: the takeover (3 bash processes, args `24172 49732`), the gated wrapper (two hand-runs: B3r in p3, a `dev_fec_select` in the p1 slot), `gated_state.ps1`, `speed_gate.ps1` and the `d91q\start.stamp` they write. Of the other 14 shell/PowerShell files, 8 point at repositories that no longer exist (`uav-gcs-d91-speed`, `uav-gcs-set4-p1`, `uav-gcs-v7-p2`) and would fail if rerun. Six queue scripts repeat the same `say/gate/end_own` code. One defect: the live `speed_gate.ps1` says 35 GB in its header and tests 28 GB in the code.
- **Folders.** 4 folders hold the only copy of untracked data (b3m-p1, b3m-p3, set4-p3, v7-bw: 77 GB, plus 14 GB in `d91q` that is scratch). 9 are 13-15 MB checkouts whose commits are all on `origin`. The two live trees are v7 (113 GB) and v7-p3 (68 GB). **`uav-gcs-v7-docs` is 13 commits ahead of `origin/v7-docs-d91`** (2.11 entries D107-D121 exist only on this disk).
- **Docs.** README, ROADMAP and PROJECT_LOG stop at 28-31.10; nothing after 31.10 (D107-D121 readings, profile 3 deploy, q7 merge, B3r on 5.11) reaches them. The stale `docs/` copies inside the code branches (v7-p3's DECISIONS.md is 1,100 lines of 16.10 against 3,065 on the docs branch) invite reading the wrong file.
- **Top 5 proposals:** (1) F-plan: one tree under the main folder, moved after ~21.11, table in section 5; (2) T4: put the seven unwired test files under the release gate and drop the double run; (3) T1: one shared helper file for the seven copied helpers (about 250 lines out of the tests); (4) S1-S3: retire the dead queue scripts and merge the `_mt` wrapper clone and the repeated gate code into one library; (5) push `v7-docs-d91` now (no risk to the chain) and refresh README/ROADMAP/LOG once.
